Design — Dados do Portal

O que muda em lib/portal/data.ts

PortalItem (actualizado)

Campos novos em PortalItem
// existente
id, title, client_label, status, completed_at, completion_note, position

// novo
due_at: string | null   ← já existe na tabela, só faltava seleccionar
files: PortalItemFile[]  ← join com checklist_item_files + event_files

PortalItemFile (novo tipo)

Interface
id: string
file_name: string
file_size: number | null
mime_type: string | null
blob_url: string   ← download directo

PortalEventData (actualizado)

Campo novo
eventFiles: PortalItemFile[]  ← ficheiros de nível evento (event_files)
items: PortalItem[]            ← cada item já traz os seus ficheiros

Query strategy

getPortalData — 3 queries (já faz 2)
1. events → (existente)
2. event_checklist_items  + due_at → (expandida)
3. checklist_item_files JOIN event_files WHERE event_id = X
4. event_files WHERE event_id = X AND NOT linked to item

Agrupa ficheiros por item em memória (JS Map). Sem N+1.
